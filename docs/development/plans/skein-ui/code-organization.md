# skein-ui: code organization

Where each thing goes, the shared interfaces and their owners, the
fixtures, the "Don't" list and the size limits. Names here are the
plan's where the design leaves them to it (`ui-web.md`, 5.1: "Their
module names are the plan's").

## 2. Modules and names

- **`jig_view::ui`** (jig 01 to 03, then skein-ui's root): `tree`
  (`Tree`, `Node`, `NodeId`, `Role`, `State`, `Owner`, `Style`, `Region`,
  `Picture`, `Shortcut`, `Modifier`, `Run`, `TextRun`, `Value`, `Key`,
  `SlotRef`, `DrawingKind`, `Drawing`), `builder` (`Builder`, `Slot`,
  `SlotId`), `diff` (`Patch`, `Attribute`, `Made`, `diff`), `view`
  (`View`), `markdown`, `binding` (`Act`, `Binding`, `BoundAct`,
  `number`), `limits` (`Limits`, `worst_case`), `outline` (`check`,
  `Fault`, `Rule`), `phrases` (the machinery). Its `mod.rs` re-exports
  them as `jig_view` does today, so that `jig_view::ui::Tree` becomes
  `skein_ui::Tree`.
- **skein-ui's new modules:** `scene` (skein 04), `look` (the look's
  names and their check, skein 03.1). The vocabulary's additions go in
  `tree`, `builder` and `diff` (skein 02); the act table, `takes`, in
  `binding` (skein 03.2).
- **skein-ui-web's modules** are the parts' names above; each part's
  platform half is a submodule `web` of its module
  (`src/<part>/web.rs`), under `#[cfg(target_arch = "wasm32")]`.
- **Words:** the design's: role, state, property, owner, binding, act,
  patch, scene, mark, look, part, inbox, turn, report.
- **Tests:** each crate's step tests in `src/tests.rs` or
  `src/tests/<area>.rs`; golden files in `src/tests/golden/` (skein's
  `testing.md`, 6); worlds and the browser tier under `tests/`.

## 4. Checks the plan adds

- **`jig_view::ui` names nothing outside itself** (jig 02.5): a step test
  in `crates/jig-view/src/tests/ui_boundary.rs` reads each file under
  `src/ui/` with `include_str!` and fails on `crate::` not followed by
  `ui::`, `jig_domain_client`, or `jig` in an identifier. It goes with
  `src/ui/` in jig 04.1.
- **The roles a binding may take** (jig 03.1): the builder asserts
  them, so every test that builds a page runs the check; skein 02.4
  adds the option, skein 03.2 the drawing.
- **One act table** (skein 03.2): `skein_ui::binding::takes`, which the
  view and the fake person's tree face both call (skein 06.3).
- **The gate's wasm32 builds and the browser suite** (skein 11.4): in
  skein's `scripts/check.sh`.

## 6. The plan's "Don't" list

- No type beside an existing one for the same thing: change the type in
  place, and its users in the same increment.
- No field or predicate that its counterpart across a boundary lacks.
- No test that checks several behaviours under one name. A table test
  whose rows are cases of one behaviour (ui.md, 17: a row per role,
  state, property, act or fault) is one behaviour.
- No lint exception in tests.
- No expected value computed by the code under test.
- **No rewrite of a moved part:** skein 01's increments copy files and
  rename paths; a change of behaviour in a moved file is a later
  increment's.
- **No re-export of skein-ui's items from jig-view**, and no alias of a
  moved type in jig (`pub use skein_ui::Tree` in jig-view, `type Tree =`).
- **No name of jig, or of a system, in skein's code** (skein's
  `AGENTS.md`), and no name of the repository downstream of jig in any
  file.
- **No `unsafe`** in `skein-ui`, `skein-ui-web` or the example's crates;
  the shell holds only what the glue's macros generate.
- **No inline script or style** in what the bundler writes, the parts
  build or the example ships (ui-web.md, 4.4).
- **No wasm-pack, npm or binaryen** (ui-web.md, 4.1).
- The words the plan forbids in code: README, "Pulse".

## 7. Size limits

A file of at most 800 lines (the pulse's `file-lines`) and a test
function of at most 40 lines, an aim: a table test keeps its rows in a
`const` beside the function, and the 40 lines count the function's
body. The moved files keep their size: a file over 800 lines that moves
is split by the increment that next changes it. Files over the limit at
the base: the README's "Rules".
