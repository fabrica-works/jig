# Session 14: the store's codecs: jig's families from schemas, the format row, sizes

Every record jig's store keeps gets a codec generated by skein's generator
from a schema of its family, and a hand-written translation from the
domain's types to the generated ones and back, exhaustive both ways, so
that a domain change to a durable field breaks the build the day it
happens (`protocol/store.md`, 5.1). This session writes the five families
(the component's own rows, notes, tasks, the core, people), their golden
bytes and bounds, the drift and fuzz tests in a codec world, the format row
that names each family's version, and the sizes check that refuses to start
when skein-kv's limits are smaller than what the domain's limits make. It
is the largest block of the store: about 3,800 hand-written lines (see
"Questions"), cut into nine increments of at most 600 each.

## What the design asks

- **Codecs** (store.md 5.1): "One schema per family, generated by skein's
  generator …, used by the component only: the core's records, each
  child's, the component's own. The domain's records are translated to
  and from the generated ones with small total functions, exhaustive both
  ways, so a domain change to a durable field breaks a translation's build
  the day it happens." "Each record carries its family's version." "Golden
  bytes per family and version; a fuzz target per family's decoder; bounds
  at their limit and one past it."
- **The format row** (5.3): "the version of the component's format (its
  keys' encoding, its frames, its own rows), the version of each of jig's
  families, the application's store version, and the deployment's id";
  "Written in the first commit …"; "Checked at open: a store whose row
  names another version of anything, or another deployment than its
  header, refuses to open, saying which."
- **Sizes** (5.4): "The component computes, from the domain's limits and
  the application's, the largest encoded key, value and commit, and
  refuses to start when skein-kv's limits are smaller (its key, value,
  operations and commit …), so a commit the root admitted is never refused
  as too large."
- **Across families** (skein's `codec.md`, 3): "No imports. A record of
  another family … travels as a `bytes N` field and is decoded by its own
  family's code."

## Choices this plan makes

- **Five schemas** in `crates/jig-protocol-store/schema/`:
  `component-v1.schema` (`family jig-store-component 1`), `notes-v1.schema`,
  `tasks-v1.schema`, `core-v1.schema`, `people-v1.schema` (`family
  jig-store-<name> 1`). Each generates `src/generated/<name>_v1.rs`,
  included as smith's is (`#[rustfmt::skip] #[path = …] pub mod
  <name>_v1;`), and `golden/<name>/v1/*.bin`.
- **One versioned row per family:** each schema ends with `versioned
  record Row { value: Value }`, whose enumeration `Value` has one variant
  per variant of the family's stored enum; the component's own family has
  one versioned record per row. The fuzz target decodes `Row`.
- **The core's rows carry the tasks child's values as bytes** (codec.md 3):
  a terminal's `End`, a projection's `Phase` and `Change`, a call's
  `Problem`, and a recalled note's `Entry` travel as `bytes N` encoded by
  the tasks or notes family's code, whose schemas declare them as records
  of their own. Small enumerations the core keeps of other children
  (`people::Proposer`, `ProposalChoice`, `EscalationDecision`,
  `tasks::ProposalKind`, `EscalationOutcome`, `ProposalOutcome`, the
  authority's `Answer` and `Finding`, the fleet's `HostKind`) are declared
  in the core's schema.
- **Types the generator lacks:** a wall time is a `u64` of nanoseconds (the
  store keeps wall times, `domain/engine.md` 5.4); a `Token` a `u64`; a
  `[u8; 16]` or `[u8; 32]` a `fixed 16` or `fixed 32`; a list of byte
  strings a `list N` of a one-field record; `Option<(u64, u64)>` an
  `option` of a two-field record.
- **The one recursion** (`New.recurring` holds a `RecurringTemplate` whose
  `batch` holds `New`): a template's members are a record `Member` without
  `recurring`, since `recurring.rs:156` refuses a member that has one; the
  translation refuses one as a `Problem`.
- **Ceilings:** each `bytes N` or `list N` takes the domain limit that
  bounds it (an aggregate where the domain bounds only a sum: `spec_bytes`,
  `authority_bytes`, `hold_bytes`, `inbox_bytes`, `amendment_bytes`,
  `policy_bytes`, `call_answer_bytes`), with a ceiling at least the worlds'
  fixtures' value and as large as keeps each type's worst case within a
  `u32`; `codec::<family>::limits` maps the domain's limits to the
  generated `Limits` and answers `None` when one passes its ceiling, which
  `sizes::check` refuses at start (jig 20's profiles must fit them).
- **The codec world** is a new package `tests/store-codecs`
  (`jig-store-codecs-world`, ordinary Rust): drift, fuzzing and memory, as
  smith's `tests/codecs`. jig 18's `tests/store` stays the store's own
  world.
- **Translations' modules** are `crates/jig-protocol-store/src/codec/<family>/*.rs`,
  none past 800 lines.

## Rules that bind it

- **"Line counts exclude generated code under `src/generated/` and its
  golden files"** (README, "Rules"), and "Generated codecs are committed
  under each codec crate's `src/generated/`, made by skein's generator from
  the crate's `schema/*.schema`, with skein's drift test, as
  `smith-transcript` does" (`code-organization.md`, section 2).
- **"A durable record's codec follows its record. Once jig 14 or jig 19 has landed a
  family's codec, an increment of any session that changes a durable
  record of that family changes its schema, its generated codec and its
  translation in the same increment, and the record's family's version
  moves at the first such change in this plan"** (README, "Rules"). In
  this session: each increment translates the family's types as they are
  on `main` when it starts, and a record another session changes later is
  that session's to follow.
- **"No increment … decodes or encodes bytes in a domain crate"**
  (`code-organization.md`, section 6): the translations are in
  `jig-protocol-store`; the domain crates gain no codec dependency.

  use skein_codegen::{generate, parse};
  use std::fs;
  use std::path::{Path, PathBuf};

  fn store() -> PathBuf {
      Path::new(env!("CARGO_MANIFEST_DIR")).join("../../crates/jig-protocol-store")
  }

  fn check(family: &str) {
      let source = fs::read_to_string(store().join(format!("schema/{family}-v1.schema"))).expect("schema readable");
      let output = generate(&parse(&source).expect("schema valid"));
      let code = store().join(format!("src/generated/{family}_v1.rs"));
      let goldens = store().join(format!("golden/{family}/v1"));
      let write = std::env::var_os("SKEIN_CODEGEN_WRITE").is_some_and(|value| value == "1");
      let again = "run SKEIN_CODEGEN_WRITE=1 cargo nextest run -p jig-store-codecs-world --test drift";
      if write {
          fs::write(&code, &output.rust).expect("write generated code");
          fs::create_dir_all(&goldens).expect("create golden directory");
      } else {
          assert_eq!(fs::read_to_string(&code).expect("generated code committed"), output.rust, "{again}");
      }
      for golden in output.goldens {
          let path = goldens.join(golden.name);
          if write {
              fs::write(&path, golden.bytes).expect("write golden bytes");
          } else {
              assert_eq!(fs::read(&path).expect("golden bytes committed"), golden.bytes, "{again}");
          }
      }
  }

  #[test]
  fn the_notes_familys_code_and_goldens_have_no_drift() {
      check("notes");
  }

  //! Arbitrary bytes through each family's row decoder (store.md 5.1, 14).
  use jig_protocol_store::notes_v1;
  use skein_lib::{Reader, Rng, Writer};

  fn notes(bytes: &[u8]) {
      if let Ok(row) = notes_v1::Row::decode(&notes_v1::CEILINGS, &mut Reader::new(bytes)) {
          let mut writer = Writer::new(usize::try_from(row.measure()).expect("measured length"));
          row.encode(&mut writer).expect("measured room");
          assert_eq!(writer.finish().as_ref(), bytes);
      }
  }

  #[test]
  fn arbitrary_notes_rows_never_panic_and_round_trip_when_they_decode() {
      let mut rng = Rng::new(0x5701_e014);

      }

- **Owners.** This crate owns every schema, generated codec and
  translation (`code-organization.md`, section 4: "the store's keys'
  encoders, families' codecs and the format row | jig 13 and jig 14"). A
  session that changes a durable record later changes its family's schema
  here, in that increment.
- **What ends what.** A row that does not decode is the component's
  `Corrupt` (jig 13's boundary), and stops the engine (store.md 7.1); a
  format row that disagrees is `OpenRefused`; a size that does not fit
  refuses the start before the component opens.
