# Session 30: `jig-protocol-client-wire`, jig's client records for both ends

jig's records between a client and the engine become a codec crate,
generated by skein's generator from one schema, version 1, used by both
ends: the exchanges' envelopes, jig's asks and their answers with
refusals' facts, the reads and their pages, the documents, the subjects
and the stream's events, signing in by the printed link, and the small
store's records. Each record is the client contract's, field for field,
as `jig-domain-client`'s `contract` module holds it and as the client's
joint world translates it today (`tests/client/src/joint/wire/`). This
session writes schemas and the little Rust around them; the translations
are jig 31's (the engine's end) and jig 32's (the client's end). It is
the meeting point of the client's protocol: both ends build on the same
generated types from their first increment.

## What the design asks

- **Records from schemas, per owner** (`client.md`, section 1):
  "`jig-protocol-client-wire` holds jig's requests, answers, reads,
  subjects and documents, generated by skein's generator, used by both
  ends."
- **The contract's, field for field** (`client.md`, section 3): "the
  joint world's translation (`../client/domain/testing.md`, section 5) is
  the map each end's translation follows, made bytes. Where the joint
  world finds the contract short, the contract changes first, and the
  wire follows."
- **What it holds** (section 3): the asks of `contract.md`, 3.2 and their
  answers, with refusals' facts; the reads of its section 6 and their
  pages; the subjects of 7.1 and their windows; the documents of 5.1; a
  run's text (7.3); the stream's hello and endings; the small store's
  records (section 10).
- **Exchanges carry their owner's version** (section 4); the stream's
  hello states the range served per owner (section 9); "pre-release, each
  range is one version".
- **"Documents are decoded whole,** into the client's types, and checked
  against the client's limits" (section 3); "the wire's generated worst cases price each document at
  the client's limits".
- **Turns cross as their bytes, smith's,** inside the documents that
  carry them (section 3).
- **No time crosses, only walls** (section 3): documents carry wall
  times; durations cross as durations.
- **Signing in by the link, natively** (section 8): "it sends the link's
  secret to the sign-in route in an exchange, and takes back its bearer
  token in the answer".
- **The small store is the wire's records,** per owner, versioned
  (section 10).

## Choices this plan makes

- **One family, `jig-client-wire 1`,** in `schema/client-v1.schema`;
  `VERSION` is 1. No magic: HTTP frames the records.
- **Two envelopes carry each owner's records:** `Keyed` (key, owner,
  version, the request's bytes) for a keyed request, and `Owned` (owner,
  version, bytes) for a read, a subject, a document and a final answer.
  jig's own records are bytes inside them too, so one path serves jig and
  an application.
- **An owner is jig or a family by number,** the application's connector
  number as the engine's root names it (`u16`).
- **Versions are `u32`,** as the contract's `VersionRange` and
  `CLIENT_VERSION` have them; small-store versions are `u16`, as
  `STORE_VERSION` has them. No width is narrowed.
- **A wall is a `u64` of nanoseconds since the epoch,** as `skein_lib::Wall`
  holds it; a duration is the schema's `duration`.
- **The stream's events are one enum, `StreamEvent`** (hello, delivery,
  text, ended). Its base64 framing in an event's data is jig 31's and
  jig 32's, over skein's `lib::base64`; this crate keeps no base64.
- **The bearer token's field** is `bytes 48` in 30.1. jig 31.1, which
  starts after jig 02 brings skein's `secret N`, changes it to `secret 48`
  and regenerates. Default: `bytes 48` here, whatever has landed.
- **The drift test and the fuzzed decoders live in the crate's world,**
  `tests/client-wire` (package `jig-client-wire-world`, ordinary Rust),
  as jig 22's `tests/worker-wire` and jig 14's `tests/store-codecs` do.
- **A cursor is opaque bytes on the wire,** `bytes N` with N 1024: jig 31
  writes it from the core's `reads::Cursor`, each key by jig 13's
  `jig_protocol_store::keys::encode`; neither this crate nor the client
  reads it.
- **Version 1 grows across 30.1 to 30.5,** each increment regenerating
  the code and goldens. No reader of the format exists outside this
  session until jig 31 and 32 start, so the version stays 1.

## Rules that bind it

- "**Generated codecs** are committed under each codec crate's
  `src/generated/`, made by skein's generator from the crate's
  `schema/*.schema`, with skein's drift test, as `smith-transcript` does.
  Generated files do not count against size limits."
  (`code-organization.md`, section 2)
- "**The client's crates** (`jig-domain-client`, `jig-view`,
  `jig-protocol-client-wire`, `jig-protocol-client-link`,
  `jig-shell-native`) depend on no engine-side crate."
  (`code-organization.md`, section 3) This crate depends on `skein-lib`
  and `skein-codec` alone.
- "No increment of this plan adds a field or predicate that its
  counterpart across a boundary lacks." (`code-organization.md`, section
  6) A record field the contract's type lacks is a question, never added.
- **Names in schemas pass `tests/boundary`'s word rules:** the generator
  writes doc comments naming each record and field, so no schema name may
  be a word of `tests/boundary/src/tests.rs`'s forbidden list or end in
  `V<digit>` or `_v<digit>`. The gate checks it.

`tests/client-wire` with the drift test and a fuzzed decoder. The
crate's rule in `tests/boundary`: it depends on
`skein-lib` and `skein-codec` only.
Needs: nothing.
Files: `crates/jig-protocol-client-wire/{Cargo.toml, schema/client-v1.schema,
src/{lib.rs, generated/v1.rs, tests.rs, tests/fixtures.rs}, golden/v1/}`;

`refused_moved()`: the contract's values written as records). Tests:
`a_keyed_request_past_its_bound_is_refused_naming_it`,
`an_owned_record_keeps_its_owners_version` (owner version `u32::MAX`, ruling 149),
`a_refusal_with_its_facts_round_trips_unchanged`,

## Interface sketches

The schema, in skein's language (`codec.md`, section 3); records the
increments add beside these follow the contract's names.

```
family jig-client-wire 1

record Family { number: u16 }
enum Owner { jig, family: Family }
# A keyed request: its key, its owner and version, the owner's record.
record Keyed { key: fixed 16 owner: Owner version: u32 request: bytes 1048576 }
# A read, a subject, a document or a final answer, in its owner's wire.
record Owned { owner: Owner version: u32 record: bytes 16777216 }
# The keyed exchange's one answer: final carries Done or Refused, in the
# request's owner's wire, or jig's for a refusal at admission.
enum Answer { final: Owned, busy, not_ready, signed_out }
record LinkSignIn { secret: bytes 64 }
record SignedIn { token: bytes 48 party: u64 expires: u64 }
enum SignInAnswer { signed_in: SignedIn, refused }
record SignOut {}
enum SignOutAnswer { signed_out }
record Served { owner: Owner first: u32 last: u32 }
record Hello { stream: fixed 16 served: list 16 Served heartbeat: duration }
record Delivery { watch: u64 document: Owned }
record Ended { watch: u64 why: WatchEnd }
enum StreamEvent { hello: Hello, delivery: Delivery, text: RunText, ended: Ended }
record Open { stream: fixed 16 watch: u64 subject: Owned }
enum OpenAnswer { admitted, refused: WatchRefusal }
record Close { stream: fixed 16 watch: u64 }
record Gone { stream: fixed 16 }
```

```rust
// jig_protocol_client_wire: the generated family and its version.
#![cfg_attr(not(test), no_std)]
#![forbid(unsafe_code)]
extern crate alloc;

#[path = "generated/v1.rs"]
pub mod v1;
pub use v1::*;

/// jig's client wire version: the one this release reads and writes.
pub const VERSION: u32 = 1;
```

- **Who owns what:** this crate owns the bytes and their bounds; the
  engine's translation is jig 31's, the client's jig 32's; an
  application's records are its own wire's (jig 33's
  `jig-test-protocol-client-wire` for jig's test application).
- **What ends what:** nothing here has a lifetime; each exchange's record
  is answered once by the record its answer enum names.
