# skein 02.s1: a golden table's cases outside its test function

A step not in the plan (ruling 110), for a fresh implementer of skein 02.
skein 02.2 made golden tables of up to 1,024 cases, one line each, inside
the test function (`testing/skein-codegen/src/emit_tests.rs:260-271`:
`fn {name}_{index}() { const CASES: [Case; N] = [...]; table(CASES); }`).
skein's own families stay under 100 cases, but smith's regenerated
`golden_0` is 233 lines (smith-transcript) and 445 (smith-channel), past
clippy's `too_many_lines` (100): smith 01.1 cannot pass its gate, and jig
05.1 will meet the same. codec.md, 6 asks generated files "that pass the
lints with no allowances".

### 02.s1 Each table's cases are an item of the module, its test one call
Scope: codec.md, 6 (generated tests, no lint allowances).
Needs: 02.2.
Files: `testing/skein-codegen/src/emit_tests.rs` (`tables` `:260-271`); `testing/skein-codegen/src/tests.rs`; `tests/codec/src/{generated,secrets,scalars,lints}/v1.rs` (regenerated with `SKEIN_CODEGEN_WRITE=1 heavy cargo nextest run -p skein-codec-tests --test drift`, ruling 101).
Shape: `tables` emits, per chunk, `const {NAME}_{index}: [Case; N] = [...];` beside the test functions, then `#[test] fn {name}_{index}() { table({NAME}_{index}); }`. The chunk sizes stay (golden 1,024, bounds 64). If clippy objects to the const (for example `large_const_arrays`), emit a `static` instead and pass it by value; never an `#[allow]`.
Test shape: in `testing/skein-codegen/src/tests.rs`, `a_table_test_is_one_call_whatever_its_cases` (an existing fixture's generated source: no `fn golden_` or `fn bounds_` body holds a `Case` array).
Proof: unit, `heavy cargo nextest run -p skein-codegen -p skein-codec-tests` once, every test passing, `git diff --stat origin/main -- tests/codec/golden` printing nothing; then skein's gate through `land`.
Don't: change a case's text, a chunk's size, a golden byte, or a test's name; add a lint exception.
Size: at most 15 lines of generator code.
Removes: the `const CASES` inside each table test.
