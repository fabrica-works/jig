# test-budgets: code organization

The plan adds no crate. It changes one public type (skein's
`stream::Read`), the code a generator emits, test fixtures, tests and
gates. This file names who owns what, where tests go, and what no
increment does.

## 1. Names

- **`Read::Arrived { max: u32 }`,** "a read of what has arrived" in
  prose (skein's lib.md, 7). Not "raw", "some", "available" or "chunk".
- **Each reader's maximum is a `const` of its own crate,** named for
  what it reads: smith's `OUTPUT_READ`, `STDERR_READ`, `GIT_READ` and
  `PROMPT_READ` (smith 01); jig's readers take a limit they already have
  (jig 05.2). No crate gains a dependency for one.
- **`_within`** suffixes the generated worst-case functions that do not
  check a family's limits (skein 02.2).
- **`NEXTEST_DOUBLE_SPAWN=0`** is set in each repository's
  `scripts/check.sh` and in skein's `heavy`, and nowhere else in code;
  the workflows and this plan's commands may name it. The check: `git
  grep -l NEXTEST_DOUBLE_SPAWN -- ':!*.md'` lists only those files.

## 3. Tests and fixtures

- **A test keeps its name,** unless its session file renames it with the
  reason (a size in its name that no longer holds).
- **Cases of one behaviour become rows** of one table test with the
  crate's table helper (jig's from `38068705f`; skein-codegen's
  generated `table`), each row labelled with the old test's name; a
  planted failing row shows, once per crate, that a failure names its
  row (testing-strategy.md, 8).
- **A fixture many tests share is a constant, or built once per test
  and borrowed;** its cost shows in its increment's Proof run; nothing
  else is measured.
- **Times are measured through `heavy --gate`,** with
  `--profile measure`, once per increment unless its Proof says
  otherwise; nothing else is measured (development.md, 4.5).

## 4. The plan's "Don't" list

No increment of this plan:

- adds a type beside an existing one for the same thing: it changes the
  type in place, and its users in the same increment;
- adds a test that checks several behaviours under one name;
- adds a lint exception in tests;
- computes an expected value with the code under test;
- drops an assertion, or changes an expected value, except a size its
  session file names with the reason the assertion holds at it;
- adds a `_ =>` arm to a match on `Read`, or an `unreachable!` arm for
  `Read::Arrived` in a production side below (a test driver that plays
  the side below a machine which never demands it puts it with the reads
  it already refuses, skein 01.1);
- changes what an exact read delivers, or makes a reader its session
  file lists as exact read what has arrived;
- builds optimized a crate that ships, a world or a kit
  (testing-strategy.md, 8, "A tool is not the code under test");
- raises a `global-timeout`, a slow period or a per-test ceiling, or
  moves a focused test to the fuzzy suite to fit the budget, unless its
  session file says so;
- edits generated code by hand, or a golden `.bin` file;
- writes the words `legacy`, `compat`, `hack` or `workaround` in code.

## 5. Size limits

- **A file:** at most 800 lines, generated code excepted. A file already
  past 800 lines grows by at most what its session file says (20 lines
  where it names no number), and is not split by this plan.
- **A test function:** at most 40 lines; a table test's rows do not
  count against it.
- **An increment:** its session file's "Size: at most N lines", a guide:
  within N × 1.5 it lands, and its report gives its count; past it, it
  asks. A Size counts lines of production code added less those removed,
  neither blank nor comments, outside tests and generated code;
  `Cargo.toml` and `Cargo.lock` count for nothing.
  The count: `git diff --numstat origin/main...HEAD -- <the increment's
  production files>`, added less removed, once; nothing finer.

## 6. What checks these rules

- **Checked:** the file and test-function limits (the supervisor's
  `plan pulse`, `file-lines: 800`); no optimized build of a crate that
  ships (`git -C ~/src/rust/<repository> diff d91a89c45 origin/main --
  '*Cargo.toml' | grep opt-level` prints nothing in jig, and the same
  from `2068257` in skein and `0305f2fd` in smith); the double spawn's
  places (section 1's check); every exhaustive match on `Read` (the
  compiler); the budgets (each repository's timeout increment).
- **Held by review, unchecked:** no `_ =>` arm or `unreachable!` arm
  for `Read::Arrived` in a production side below; no assertion dropped
  or expected value changed beyond a named size; a test keeping its
  name; a row's case under 1 ms of work; behaviour unchanged where
  production code changes; at most 30 `smoke-tools` runs (their run
  identifiers are in the smith commit bodies). The supervisor samples
  them in its hourly check (development.md, 14).
